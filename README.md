# منصة المنيو الإلكتروني وبوابات الطلب عبر واتساب (Multi-tenant SaaS)

منصة خفيفة وسريعة (HTML/CSS/JS بدون أي خطوة بناء) لإنشاء منيو إلكتروني وبوابات **طلب / حجز / استفسار / تبرع / استشارة** لأي نشاط،
تعتمد على **Click-to-Chat الرسمي (`wa.me`)** — بدون أي بوت واتساب، فلا خطر حظر للأرقام.

```
domain.com/?store=slug          ← صفحة المتجر العامة (PWA قابلة للتثبيت، عربي/English)
domain.com/manage?store=slug    ← لوحة التاجر (PIN)
domain.com/admin                ← لوحة الإدارة العامة (Supabase Auth + تحقق بخطوتين)
```

## الميزات

**صفحة العميل:** 5 أوضاع تشغيل (طلبات، حجوزات، استفسار ومعاينة، تبرعات، استشارات قانونية) • تصميم بأسلوب تطبيقات التوصيل •
11 قالباً + لون مخصص • عربي/English • رمز الريال الرسمي • بنر عرض بعداد تنازلي • أوقات عمل لكل يوم بفترتين وبعد منتصف الليل •
سعر قبل الخصم • مخزون محدود • كوبونات خصم • مناطق توصيل برسوم مختلفة • حد أدنى للطلب • تقويم توفر للحجوزات •
«أعد طلبك المعتاد» • تثبيت كتطبيق PWA • رسالة واتساب منسّقة بإطار وأقسام.

**لوحة التاجر (4 تبويبات):** المنيو (إضافة سريعة، منيو من صورة بالذكاء الاصطناعي، إظهار/إخفاء، تعديل السعر، ترتيب بالأسهم) •
الإعدادات (التوصيل، المناطق، الحد الأدنى، أوقات العمل، الإغلاق الطارئ، PIN) • التصميم • العروض (البنر، العداد، الكوبونات) •
وسجل الطلبات بحالاته (جديد / مؤكد / مكتمل / ملغي) مع إرجاع المخزون عند الإلغاء، وإحصائيات برسوم بيانية.

**لوحة الإدارة:** إنشاء متجر برابط و QR • تجديد +30 يوم • إيقاف/تفعيل • دخول لوحة التاجر للمساعدة • رسالة تذكير بالتجديد •
حذف نهائي بتأكيد • سجل عمليات • تحقق بخطوتين (TOTP).

## التشغيل

### الطريقة السريعة (Supabase CLI)
```bash
npm i -g supabase && supabase login
export SUPABASE_PROJECT_REF=xxxx SUPABASE_ANON_KEY=... APP_URL=https://your-domain.com ANTHROPIC_API_KEY=sk-ant-...
./scripts/deploy.sh
```
يرحّل قاعدة البيانات، وينشر الدوال الأربع، ويضبط الأسرار، ويحدّث `config.js`، ثم يطبع الخطوات المتبقية.

### يدوياً
1. **قاعدة البيانات:** في **SQL Editor** شغّل `20261126000000_init.sql` ثم `20261127000000_features.sql` (آمنة لإعادة التشغيل).
   تأكد أن مخطط `private` **غير** مكشوف في **Project Settings → API → Exposed schemas**.
2. **المدير:** أنشئ حساباً من **Authentication → Users** ثم:
   ```sql
   insert into private.admins (user_id) select id from auth.users where email = 'admin@example.com';
   ```
   فعّل **MFA (TOTP)** في **Authentication → Providers**، ثم من لوحة الإدارة زر 🔐 لتفعيل التحقق بخطوتين.
3. **الدوال:**
   ```bash
   for f in sign-upload vision-menu manifest cleanup-media; do supabase functions deploy $f --no-verify-jwt; done
   supabase secrets set APP_URL=https://your-domain.com ANTHROPIC_API_KEY=sk-ant-... CLEANUP_SECRET=$(openssl rand -hex 24)
   ```
   - `VISION_MODEL` اختياري (الافتراضي `claude-opus-5-5`؛ للتوفير `claude-sonnet-5-5` أو `claude-haiku-5-5`).
4. **الواجهة:** عدّل `public/assets/js/config.js` وارفع المشروع على **Vercel** (`vercel.json` + `middleware.js` جاهزة) أو **Netlify** (`netlify.toml`).
   أضف في الاستضافة متغيري البيئة `SUPABASE_URL` و `SUPABASE_ANON_KEY` لتعمل **معاينة الروابط** في واتساب.
5. **تنظيف الصور:** عدّل `supabase/cron.sql` (رقم المشروع والسر) وشغّله — يحذف يومياً الصور غير المستخدمة الأقدم من 24 ساعة.
6. **التجربة:** راجع `docs/DEVICE_TESTING.md` على آيفون وأندرويد.

## الحماية

| المتطلب | التنفيذ |
|---|---|
| RLS صارم | الزوار يقرؤون المتاجر النشطة غير المنتهية فقط؛ لا كتابة مباشرة لأي دور، كل الكتابة عبر RPC بقائمة حقول بيضاء. |
| رمز PIN | مُجزّأ bcrypt في `private.store_secrets` (غير مكشوف عبر API ولا Realtime). قفل 15 دقيقة بعد 5 محاولات خاطئة. |
| المدير | Supabase Auth + `private.admins` + **تحقق بخطوتين**: إذا فعّله المدير تُرفض كل عمليات الإدارة بدون جلسة `aal2`. كل عملية تُسجَّل في `private.audit_log`. الحذف النهائي يشترط كتابة رابط المتجر. |
| بيانات الطلبات | اسم العميل وجواله وعنوانه تُحفظ في `analytics_events.meta` ولا يقرؤها إلا تاجر المتجر عبر رمز جلسته. |
| الكوبونات | في مخطط خاص؛ التحقق عبر RPC مع حد محاولات لمنع التخمين؛ النسبة القصوى 90%. |
| Vision API | في الخادم فقط، 5 صور يومياً لكل متجر مع إرجاع الرصيد عند الفشل. |
| Storage | JPEG/PNG/WebP فقط، 2MB، رفع عبر روابط موقّعة فقط، ضغط في المتصفح، وتنظيف دوري للصور اليتيمة. |
| analytics_events | إلحاق فقط (Trigger يمنع التعديل/الحذف)، قيود CHECK، Rate limit لكل IP. |
| XSS | لا `innerHTML` إطلاقاً، `safeUrl()` للروابط، تنظيف في الخادم، CSP صارم، وتهريب HTML في معاينة الروابط. |

## العملة واللغة
- **رمز الريال ( ⃁ U+20C1)** في الواجهة عبر خط OFL مستضاف ومقصور على هذا الحرف. في رسائل واتساب يُستخدم **﷼** لأنه مدعوم في كل الأجهزة (`CURRENCY` و `CURRENCY_TEXT` في `config.js`).
- **عربي / English** في الواجهات الثلاث مع قلب الاتجاه تلقائياً؛ `&lang=en` في الرابط يفتح بالإنجليزية. رسائل واتساب تبقى بالعربية لأنها موجهة للتاجر.

## ملاحظات
- Click-to-Chat لا يؤكد أن العميل ضغط «إرسال» داخل واتساب؛ السجل يسجّل لحظة فتح واتساب، والتاجر يؤكد الطلب من سجل الطلبات.
- جدول `stores` مقروء للزوار (للمتاجر النشطة) ليعمل Realtime؛ يكشف أسماء المتاجر وأرقام واتسابها، وهي عامة أصلاً في صفحاتها.
- الاشتراكات تُجدَّد يدوياً من لوحة الإدارة؛ لا يوجد دفع إلكتروني للاشتراك (يحتاج حساب بوابة دفع مثل Moyasar أو Tap).
